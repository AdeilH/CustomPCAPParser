# ClickFiller — Elasticsearch → ClickHouse transfer tool

## Context

The pipeline is: pcaps → **PcapParser** (zero-dep Rust library) → **ElasticFiller** (zero-dep Rust bin) → Elasticsearch index `xdp-messages` (flat JSON docs, ~25 scalar fields, deterministic IDs `file:packet:n`, ES 9.2.2 at `127.0.0.1:9200`, auth `elastic-admin`/`elastic-password`). `/home/Adeel/Projects/Trading/ClickFiller/` exists and is empty — the user wants a new **Rust project there that moves that data into ClickHouse**. A web interface is explicitly deferred ("discuss later"); this project is transfer-only, but README will note the web UI as planned.

Confirmed with user: **one-shot resumable migration** (watch mode later) and **pure-std, zero dependencies** — matching the house style (PcapParser has from-scratch zstd; ElasticFiller a hand-rolled HTTP client).

## ClickHouse schema (generated by `schema.rs`, `CREATE TABLE IF NOT EXISTS`)

```sql
CREATE TABLE IF NOT EXISTS xdp_messages (
  ts                  DateTime64(9, 'UTC'),   -- from "@timestamp" (renamed; full ns string preserved in _source)
  es_id               String,                 -- ES _id ("file:packet:n"), provenance + dedup
  file                LowCardinality(String),
  msg_type            LowCardinality(String),
  msg_type_id         UInt16,
  symbol              LowCardinality(String) DEFAULT '',
  symbol_index        Nullable(UInt32),       -- absent on non-symbol messages
  source_time         UInt32 DEFAULT 0,
  source_time_ns      UInt32 DEFAULT 0,
  product_id          UInt8  DEFAULT 0,
  channel_id          UInt8  DEFAULT 0,
  partition_id        UInt32 DEFAULT 0,
  symbol_seq_num      UInt32 DEFAULT 0,
  security_status     LowCardinality(String) DEFAULT '',
  halt_condition      LowCardinality(String) DEFAULT '',
  current_refresh_pkt UInt16 DEFAULT 0,
  total_refresh_pkts  UInt16 DEFAULT 0,
  last_seq_num        Nullable(UInt32),       -- explicit null in ES ("absent on some channels")
  last_symbol_seq_num Nullable(UInt32),
  order_id            UInt64 DEFAULT 0,
  new_order_id        UInt64 DEFAULT 0,
  trade_id            UInt32 DEFAULT 0,
  price               UInt32 DEFAULT 0,       -- raw unscaled numerator, same convention as ES
  volume              UInt32 DEFAULT 0,
  side                LowCardinality(String) DEFAULT '',
  firm_id             LowCardinality(String) DEFAULT '',
  position_change     UInt8  DEFAULT 0,
  printable           UInt8  DEFAULT 0,
  trade_conditions    LowCardinality(String) DEFAULT '',
  reference_price     UInt32 DEFAULT 0,
  paired_qty          UInt32 DEFAULT 0
) ENGINE = ReplacingMergeTree
PARTITION BY toDate(ts)
ORDER BY (ts, es_id);
```
Widths verified against `PcapParser/src/feeds/xdp.rs` (u64 order ids, u32 prices/seq nums/partition id, u16 refresh counters, u8 flags). Nullable only where ES null/absence is meaningful; elsewhere absent → 0/'' (documented). **ReplacingMergeTree + ORDER BY (ts, es_id)** makes reruns and the client's reconnect-resend idempotent (duplicates collapse during merges; point queries use FINAL).

## Transfer pipeline (one-shot, resumable)

1. Ping ES (`GET /` → 200 + cluster_name) and CH (`GET /ping` → "Ok.").
2. `CREATE TABLE IF NOT EXISTS` (always; `--create-table-only` exits after).
3. `POST /{index}/_pit?keep_alive=5m`.
4. Page loop (`--batch`, default 5000 docs, 4 MB byte cap — same thresholds as ElasticFiller):
   `POST /_search` with `{"size":B,"pit":{"id":...},"sort":[{"@timestamp":"asc"},{"_id":"asc"}]}` + `search_after` of the previous page's last sort values. Both sort keys are document-intrinsic (not `_shard_doc`), so the position is **valid across PIT instances — resume is exact**. Empty page → done, `DELETE /_pit`.
5. Each hit: parse `_source` → project through `schema.rs` (rename `@timestamp`→`ts`, inject `es_id`, known columns in order, unknown keys dropped) → append NDJSON row.
6. Insert via `POST /?query=INSERT INTO <t> FORMAT JSONEachRow&date_time_input_format=best_effort&input_format_null_as_default=1&input_format_skip_unknown_fields=1`.
7. After each successful insert: **checkpoint file** (default `clickfiller-checkpoint.json`, `--checkpoint PATH`) written atomically (temp+rename): `{"sort": [raw values verbatim], "docs": N}`. `--resume` loads it, opens a fresh PIT, starts at that position; successful completion deletes the file.
8. Progress per page on stderr, sibling style: `docs done/total` (total from first page's `hits.total`), docs/s, elapsed, current file.
9. Any error is fatal with a clear message (checkpoint holds the resume point). `--limit N` stops after N docs for smoke tests.

`--verify`: ES `_count` vs `SELECT count(), min(ts), max(ts)` from CH, printed side by side.

Defaults mirror ElasticFiller: `--es-host 127.0.0.1 --es-port 9200 --es-index xdp-messages --es-user elastic-admin --es-pass elastic-password`, `--ch-host 127.0.0.1 --ch-port 8123 --ch-table xdp_messages --ch-user default --ch-pass clickhouse-password`.

## Verification

1. `cargo build --release` and `cargo test` in ClickFiller (json parser, DDL/projection, percent-encoding, chunked framing tests ported with es.rs).
2. `docker compose up -d`; `cargo run --release -- --create-table-only`; confirm with `curl 'http://127.0.0.1:8123/?query=SHOW+CREATE+TABLE+xdp_messages'`.
3. If the ES cluster is running with data (user's machine): `make transfer` first with `--limit 10000`, `make verify`, then the full run; spot-check one known `es_id` both sides.
4. Crash-resume test: interrupt a transfer, `make resume`, confirm final CH count exactly equals ES count.
